FEATURES

Everything a channel queue needs

Designed for reliability first: atomic claiming, retries, a dead-letter table and a secret-protected webhook.

Scheduled publishing

A cron processor paced at 10 s per post — safely under Telegram's flood limits, resumable at any time.

Album support

Members of a media_group travel together via sendMediaGroup — each keeping its own caption.

Secret-protected webhook

Validates the X-Telegram-Bot-Api-Secret-Token header; strangers probing your Worker get a 403.

Smart retries

Temporary failures retry up to 3 times, and Telegram's 429 retry_after is honoured to the second.

Dead letter queue

Permanent failures are stored with their exact cause — review, bulk-restore or purge from the panel.

No duplicate sends

Atomic UPDATE … RETURNING claiming hands each item to exactly one processor — even under concurrent crons.

Stats & preview

Pending, failures, 24-hour and all-time counters — plus a peek at the 5 newest queued items.

Full admin control

Flush, pause, purge with inline confirmation, and a master power switch — all from the chat.

ARCHITECTURE

Six focused modules, one D1 database

The webhook only feeds the queue; the cron trigger drains it. Clean separation keeps every concern testable.

QUICK START

Live in about five minutes

No servers, no Docker, no billing alerts. A free Cloudflare account and a bot token are all you need.

1

Clone & install

git clone https://github.com/CheginiSoroush/KV-Dumper.git
cd KV-Dumper && npm install
2

Create the D1 database & config

npx wrangler d1 create kv-dumper-db
# copy the database_id into wrangler.toml
cp wrangler.toml.example wrangler.toml
npm run db:init
3

Set the secrets

npx wrangler secret put BOT_TOKEN        # from @BotFather
npx wrangler secret put ADMIN_ID         # your numeric id
npx wrangler secret put CHANNEL_ID       # e.g. @mychannel
npx wrangler secret put WEBHOOK_SECRET   # openssl rand -hex 32
4

Deploy & register the webhook

npm run deploy
# then open in a browser:
https://kv-dumper.<subdomain>.workers.dev/setwebhook?secret=<WEBHOOK_SECRET>
🔐

Security first: only your ADMIN_ID can command the bot, every webhook call must carry the secret header, and user content is never parsed as HTML in channel posts.

TUNING

One file controls the behaviour

Every timing and limit lives in src/constants.js — tweak values, not logic.

Constant Default Purpose
SEND_INTERVAL_MS10 000Pause between channel posts
RETRY_BACKOFF_MS5 000Pause after a temporary failure
MAX_RETRIES3Retries tolerated before dead-lettering
ALBUM_MAX10Max album members (Telegram limit)
PROCESSOR_BUDGET_MS60 000Wall-clock budget of one cron tick
LOCK_LEASE_MS180 000Processor-lock lease; must exceed the budget
STALE_CLAIM_MS300 000Recovery threshold for rows stuck in “sending”
